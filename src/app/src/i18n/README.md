# Internationalization

Lemonade's renderer uses a data-driven locale registry. Application code does not maintain a union or list such as `en | de | ...`.

## Layout

```text
src/i18n/
  core.tsx
  types.ts
  generated/locales.generated.ts
  locales/
    en-US/
      manifest.json
      common.json
      app.json
      navigation.json
      settings.json
      monitor.json
      chat.json
      models.json
      router.json
      inspect.json
      mcp.json
      backends.json
      logs.json
      apps.json
    de-DE/
      ...
```

Exactly one locale manifest has `"source": true`. Missing target-locale keys fall back to that source locale.

## Add a language

```bash
npm run i18n:add -- zh-Hans
```

The command:

1. canonicalizes and validates the BCP-47 locale tag;
2. derives text direction from the locale's script;
3. creates a manifest and empty namespace files;
4. regenerates the locale registry.

Empty files intentionally use source-locale fallback until translations are added. There is no language switch statement or hardcoded language-label table to update.

Use `zh-Hans` for Simplified Chinese and `zh-Hant` for Traditional Chinese. Runtime locale matching maximizes BCP-47 tags with `Intl.Locale`, so a future registered `zh-Hans` locale can match `zh-CN` while a `zh-Hant` request is not silently mapped to Simplified Chinese.

## Commands

```bash
npm run i18n:sync   # validate locale folders and regenerate the registry
npm run i18n:check  # validate catalogs and fail if the generated registry is stale
npm run i18n:add -- <bcp47-locale>
```

Renderer dev/build scripts regenerate the registry automatically. Type checking runs `i18n:check` first.

## Using translations

```tsx
const { t } = useI18n('settings');
return <h2>{t('language.label')}</h2>;
```

Interpolation uses `{{name}}`:

```json
{ "active": "Active locale: {{locale}}" }
```

Plural values may use CLDR categories (`zero`, `one`, `two`, `few`, `many`, `other`) and are selected with `Intl.PluralRules` when `count` is passed.

The provider also exposes locale-aware number, date, list, relative-time, and locale-display-name formatting through the platform `Intl` APIs.

## Runtime behavior

- An explicit locale preference is stored as `lemonade:locale`.
- With no explicit preference, `navigator.languages` is followed in preference order.
- `document.documentElement.lang`, `dir`, and `data-locale` update on every switch.
- Locale names in the settings picker are generated by `Intl.DisplayNames`, not translated by hand.
- Global search normalization is Unicode-aware so non-Latin scripts such as Chinese remain searchable.
