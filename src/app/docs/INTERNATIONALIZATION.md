# Internationalization

Lemonade's renderer uses a data-driven BCP-47 locale registry. Application code does not maintain a language union or switch such as `en | de | ...`, and components do not branch on language codes.

## What is generated and what is not

Translation catalogs under `src/i18n/locales/<locale>/*.json` are source-controlled content. They are intentionally **not** generated translations: translators or maintainers edit those files and review the wording like any other UI copy.

Only `src/i18n/generated/locales.generated.ts` is generated. It is an import registry built from the locale folders, so adding a locale never requires editing an application-level language list.

This distinction is important:

- **translation resource:** `de-DE/chat.json`, `en-US/models.json`, and similar files containing UI copy;
- **generated registry:** `generated/locales.generated.ts`, which discovers and imports those resources;
- **application code:** consumes semantic keys such as `t('actions.cancel')` and never asks whether the active language is German, English, Chinese, or another locale.

## Layout

```text
src/i18n/
  core.tsx
  types.ts
  generated/locales.generated.ts
  locales/
    en-US/
      manifest.json
      common.json
      app.json
      navigation.json
      settings.json
      monitor.json
      chat.json
      models.json
      router.json
      inspect.json
      mcp.json
      backends.json
      logs.json
      apps.json
    de-DE/
      ...
```

Exactly one locale manifest has `"source": true`. Missing target-locale keys fall back to that source locale. A locale that is intended to be structurally complete may also set `"complete": true`; `i18n:check` then requires every source namespace and translation key to be present. This checks catalog coverage and interpolation placeholders such as `{{count}}`; it does not judge translation quality. German uses this flag, while a newly added locale can remain intentionally partial during translation.

## Add a language

```bash
npm run i18n:add -- zh-Hans
```

The command:

1. canonicalizes and validates the BCP-47 locale tag;
2. derives text direction from the locale's script;
3. creates a manifest and empty namespace files;
4. regenerates the locale registry.

Empty files intentionally use source-locale fallback until translations are added. There is no language switch statement or hardcoded language-label table to update.

Use `zh-Hans` for Simplified Chinese and `zh-Hant` for Traditional Chinese. Runtime locale matching maximizes BCP-47 tags with `Intl.Locale`, so a registered `zh-Hans` locale can match `zh-CN` while a `zh-Hant` request is not silently mapped to Simplified Chinese.

## Commands

```bash
npm run i18n:sync   # validate locale folders and regenerate the registry
npm run i18n:check  # validate catalogs, complete locales, UI i18n contracts, and registry freshness
npm run i18n:add -- <bcp47-locale>
```

Renderer dev/build scripts regenerate the registry automatically. Type checking runs `i18n:check` first.

## Using translations

```tsx
const { t } = useI18n('settings');
return <h2>{t('language.label')}</h2>;
```

Interpolation uses `{{name}}`:

```json
{ "active": "Active locale: {{locale}}" }
```

Plural values may use CLDR categories (`zero`, `one`, `two`, `few`, `many`, `other`) and are selected with `Intl.PluralRules` when `count` is passed.

The provider also exposes locale-aware number, date, list, relative-time, and locale-display-name formatting through the platform `Intl` APIs.

## Dynamic remote content

Remote services can return human-readable text that is not owned by the renderer. The Apps Marketplace is an example: app names, descriptions, and categories arrive from the marketplace feed.

For this case `useI18n()` exposes `tOptional()`. Locale catalogs may provide overrides keyed by stable remote identifiers. If no override exists, the renderer keeps the remote text instead of displaying a missing-key marker. This means a newly published app appears immediately without a renderer release, while known entries can still be fully localized.

The source locale can declare an override key with `null`. That reserves the key for other locales without duplicating or freezing the English text from the remote feed.

## Runtime behavior

- An explicit locale preference is stored as `lemonade:locale`.
- With no explicit preference, `navigator.languages` is followed in preference order.
- `document.documentElement.lang`, `dir`, and `data-locale` update on every switch.
- Locale names in the settings picker are generated by `Intl.DisplayNames`, not translated by hand.
- Global search normalization is Unicode-aware so non-Latin scripts such as Chinese remain searchable.
