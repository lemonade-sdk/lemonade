llama.cpp-Specific API

This page documents Lemonade's llama.cpp-specific compatibility surface. Lemonade forwards each of these requests to a llama.cpp server: rerank to the model it names, and slots and tokenize, which name no model, to the most recently used loaded model.

Method Endpoint Description Modality
POST /v1/rerank Score documents against a query query + documents -> relevance-scored documents
POST /v1/systemone Answer typed questions about content with a decision model state + questions -> one answer per question
GET /v1/slots Read each slot's processing state slots state
POST /v1/slots/{id}?action=save Save the prompt cache of the specified slot to a file prompt cache
POST /v1/slots/{id}?action=restore Restore the prompt cache of the specified slot from a file prompt cache
POST /v1/slots/{id}?action=erase Erase the prompt cache of the specified slot prompt cache
POST /v1/tokenize Tokenize text tokenization

POST /v1/rerank

Scores each document against a query. Only llama.cpp reranker models, such as bge-reranker-v2-m3-GGUF, serve this endpoint.

Also served at /v1/reranking and /v1/reranker. Requires LEMONADE_API_KEY when it is set.

Parameters

Parameter Required Description Status
query Yes The search query text.
documents Yes Documents to score against the query.
model Yes The model to run; loaded on first use.
ctx_size No Lemonade extension: context size to load the model with, when this request loads it. Ignored when the model is already loaded.

Example

Invoke-WebRequest `
  -Uri "http://localhost:13305/v1/rerank" `
  -Method POST `
  -Headers @{ "Content-Type" = "application/json" } `
  -Body '{
      "model": "bge-reranker-v2-m3-GGUF",
      "query": "What is the capital of France?",
      "documents": [
        "Paris is the capital of France.",
        "Berlin is the capital of Germany.",
        "Madrid is the capital of Spain."
      ]
    }'

curl http://localhost:13305/v1/rerank \
  -H "Content-Type: application/json" \
  -d '{
      "model": "bge-reranker-v2-m3-GGUF",
      "query": "What is the capital of France?",
      "documents": [
        "Paris is the capital of France.",
        "Berlin is the capital of Germany.",
        "Madrid is the capital of Spain."
      ]
    }'

Response: 200 OK

{
  "model": "bge-reranker-v2-m3-GGUF",
  "object": "list",
  "results": [{"index": 0, "relevance_score": 8.621444702148438}, ... 2 more],
  "usage": {"prompt_tokens": 51, "total_tokens": 51}
}

Response format

  • model - The model that scored the documents.
  • object - Always "list".
  • results - Every input document with its score, sorted by relevance_score, highest first.
  • index - The document's position in documents.
  • relevance_score - How relevant the model rates the document; higher is more relevant.
  • usage - Tokens processed.
  • prompt_tokens - Tokens in the query and documents.
  • total_tokens - All tokens processed.

Errors

Status Code When
400 invalid_json The body is not a JSON object
400 missing_argument A required argument is missing
400 invalid_argument An argument or a value nested in it has the wrong JSON type, or a value its schema does not list
400 model is not a llama.cpp model
400 model_load_refused The backend refuses the requested model as it is registered, before it starts anything, such as a decision model whose GGUF type the bundled llama.cpp does not support
404 model_not_supported The requested model is filtered out on this system, such as an NPU model without an NPU
404 model_not_found The requested model is not in the registry
409 router_residency_conflict Loading the requested model would evict a model that a collection.router model needs resident on the same NPU
409 slots_pinned_error Every loaded model of the requested model's type is pinned, so none can be unloaded to make room
500 The backend reports an error; the backend's own status replaces this one when it sends one
500 The request fails unexpectedly
500 model_load_error Loading the requested model fails for another reason, such as a failed download or a backend that does not start

POST /v1/systemone

Asks a decision model typed questions about one piece of content and returns one answer per question, without generating tokens. lemond forwards the request to the backend unchanged, including the order of each question's options: llama-server builds the prompt from the template in the GGUF, and FastFlowLM serves its d3 models on the NPU with flm serve --decision. Only llamacpp and flm models labelled classification and systemone, such as Laya-GGUF or d3-lite-FLM, serve this endpoint.

Requires LEMONADE_API_KEY when it is set.

Parameters

Parameter Required Description Status
model No The classification model. Optional when exactly one classification model is loaded; that model is used.
state Yes The content to judge. A value that is not a string reaches the model as JSON text. null asks about the images only; the backend refuses it for decision types that need text.
questions Yes Maps each question id to a question, which the model answers independently of the others. A question has a type (choice, score or noul), instructions, and criteria: for choice, an object that maps each option to a description or null; for score, an array of 2 to 10 levels, lowest first; for noul, optional true and false descriptions.
images No Data URLs of images to judge with the state. A llamacpp model must load with an mmproj file, and llama-server decides which decision types read images. FLM's d3 models read images without one.
ctx_size No Lemonade extension: context size to load the model with, when this request loads it. Ignored when the model is already loaded.

Cuts

lemond adds truncated to each answer. A laya model (Laya, Julia-1) cuts a long option or a long question without saying so, so lemond refuses such a question with 400 instead.

Answer Quality

Answers depend on the model, on the wording of each question, and on the order of a choice question's options. Test a question with the model that serves it before a router policy relies on its scores.

Images

Register the model with its projector file, for example on /v1/pull: {"model_name": "user.my-decider", "checkpoint": "<repo>:<variant>", "mmproj": "<mmproj file>.gguf", "recipe": "llamacpp", "labels": ["classification", "systemone"]}. Then send images as data URLs (data:image/png;base64,...), with or without a state.

Example

Invoke-WebRequest `
  -Uri "http://localhost:13305/v1/systemone" `
  -Method POST `
  -Headers @{ "Content-Type" = "application/json" } `
  -Body '{
      "model": "Laya-GGUF",
      "state": "Customer message: I was charged twice for my order last week and nobody has replied.",
      "questions": {
        "route": {
          "type": "choice",
          "instructions": "Which team should handle this?",
          "criteria": {"billing": null, "shipping": null, "technical": null}
        },
        "angry": {"type": "noul", "instructions": "Is the customer angry?"},
        "urgency": {
          "type": "score",
          "instructions": "How urgent is this?",
          "criteria": ["can wait", "this week", "today", "right now"]
        }
      }
    }'

curl http://localhost:13305/v1/systemone \
  -H "Content-Type: application/json" \
  -d '{
      "model": "Laya-GGUF",
      "state": "Customer message: I was charged twice for my order last week and nobody has replied.",
      "questions": {
        "route": {
          "type": "choice",
          "instructions": "Which team should handle this?",
          "criteria": {"billing": null, "shipping": null, "technical": null}
        },
        "angry": {"type": "noul", "instructions": "Is the customer angry?"},
        "urgency": {
          "type": "score",
          "instructions": "How urgent is this?",
          "criteria": ["can wait", "this week", "today", "right now"]
        }
      }
    }'

Response: 200 OK

{
  "model": "Laya-GGUF",
  "answers": {
    "route": {
      "type": "choice",
      "choice": "billing",
      "probabilities": {"billing": 0.9914327368198715, ... 2 more},
      "confidence": 0.9871491052298071
    },
    ... 2 more
  },
  "usage": {"input_tokens": 136, "output_tokens": 0}
}

Response format

  • model - The model that answered.
  • answers - One answer for each question, keyed by question id.
  • One question's answer. Its fields depend on the question's type.
    • type - The question's type.
    • choice - choice questions: the most likely option.
    • score - score questions: the expected level index, from 0 to the number of levels minus one.
    • legend - score questions: each level's text, keyed by level index.
    • The level's text.
    • probabilities - choice and score questions: the probability of each option, keyed by option for choice and by level index for score. The probabilities sum to 1.
    • The probability, in [0, 1].
    • confidence - choice and score questions: how clearly the model prefers its answer; 0 when every option is equally likely.
    • noul - noul questions: the probability that the answer is true.
    • truncated - Added by Lemonade. false when the decision type refuses a state that does not fit instead of cutting it. Absent when it can cut the state without saying so (lfm2-d1-omni; h2o-lightning with a state over 32,000 bytes), so absence means unknown.
    • error - FastFlowLM: max_length_exceeded when this question does not fit in the model's context, so the answer has no scores. The other questions are still answered; when every question is refused, the status is 400 context_length_exceeded instead.
    • message - With error: why the question was refused, with its token count and the context size.
  • usage - Tokens processed.
  • input_tokens - Prompt tokens across all questions.
  • output_tokens - Always 0, because the model generates no tokens.

Errors

Status Code When
400 invalid_json The body is not a JSON object
400 missing_argument A required argument is missing
400 invalid_argument An argument or a value nested in it has the wrong JSON type, or a value its schema does not list
400 model is omitted and not exactly one classification model is loaded
400 model lacks the classification or systemone label, or its backend does not answer SystemOne questions; checked before it loads
400 The backend rejects a question, such as a score question with one level; the backend's status replaces this one
400 A laya model (Laya, Julia-1) would cut an option or the question; llama-server cuts them without saying so
400 context_length_exceeded state and a question do not fit in the model's context. FastFlowLM refuses only the questions that do not fit: while another question fits, the status is 200 and each refused answer carries "error": "max_length_exceeded"
400 model_load_refused The backend refuses the requested model as it is registered, before it starts anything, such as a decision model whose GGUF type the bundled llama.cpp does not support
404 The model is unloaded while the request waits for it
404 model_not_supported The requested model is filtered out on this system, such as an NPU model without an NPU
404 model_not_found The requested model is not in the registry
409 router_residency_conflict Loading the requested model would evict a model that a collection.router model needs resident on the same NPU
409 slots_pinned_error Every loaded model of the requested model's type is pinned, so none can be unloaded to make room
500 The backend reports an error; the backend's own status replaces this one when it sends one
500 The request fails unexpectedly
500 model_load_error Loading the requested model fails for another reason, such as a failed download or a backend that does not start
501 images is sent to a model that reads no images, or that loaded without mmproj

Requires LEMONADE_API_KEY when it is set.

Response format

  • n_prompt_tokens - Tokens in the slot's current prompt.
  • n_prompt_tokens_cache - Prompt tokens reused from the slot's cache instead of processed again.
  • n_prompt_tokens_processed - Prompt tokens processed for the current request.
  • params - Sampling parameters of the slot's last request.
  • speculative - Whether the slot uses speculative decoding.

500 The request fails unexpectedly

POST /v1/slots/{id}

Saves a slot's prompt cache to a file, restores it from one, or erases it, so a conversation can resume where it left off.

Requires LEMONADE_API_KEY when it is set.

Parameters

Parameter Required Description Status
id (path) Yes The slot to act on.
filename No File to save to or restore from, relative to --slot-save-path. Required for save and restore.
action (query) Yes save writes the slot's prompt cache to filename, restore reads it back from filename, and erase clears the slot.

Every action needs llama.cpp started with --slot-save-path. Set it for every load with lemonade config set llamacpp.args="--slot-save-path /path/to/slot/saves" (see Server Configuration), or for one load with llamacpp_args on POST /v1/load.

Examples

Save

Invoke-WebRequest `
  -Uri "http://localhost:13305/v1/slots/0?action=save" `
  -Method POST `
  -Headers @{ "Content-Type" = "application/json" } `
  -Body '{"filename": "my_conversation_cache.bin"}'

curl "http://localhost:13305/v1/slots/0?action=save" \
  -H "Content-Type: application/json" \
  -d '{"filename": "my_conversation_cache.bin"}'

Response: 200 OK

{
  "id_slot": 0,
  "filename": "my_conversation_cache.bin",
  "n_saved": 46,
  "n_written": 5277108,
  "timings": {"save_ms": 8.225}
}

Restore

Invoke-WebRequest `
  -Uri "http://localhost:13305/v1/slots/0?action=restore" `
  -Method POST `
  -Headers @{ "Content-Type" = "application/json" } `
  -Body '{"filename": "my_conversation_cache.bin"}'

curl "http://localhost:13305/v1/slots/0?action=restore" \
  -H "Content-Type: application/json" \
  -d '{"filename": "my_conversation_cache.bin"}'

Response: 200 OK

{
  "id_slot": 0,
  "filename": "my_conversation_cache.bin",
  "n_restored": 46,
  "n_read": 5277108,
  "timings": {"restore_ms": 1.161}
}

Erase

Invoke-WebRequest `
  -Uri "http://localhost:13305/v1/slots/0?action=erase" `
  -Method POST

curl -X POST "http://localhost:13305/v1/slots/0?action=erase"

Response: 200 OK

{"id_slot": 0, "n_erased": 46}

Response format

  • id_slot - The slot acted on.
  • filename - save and restore: the file written or read.
  • n_saved - save: tokens written.
  • n_restored - restore: tokens read.
  • n_written - save: bytes written.
  • n_read - restore: bytes read.
  • n_erased - erase: tokens cleared.
  • timings - save and restore: how long the file operation took.

Errors

Status Code When
400 invalid_json The body is not a JSON object
400 missing_argument A required argument is missing
400 invalid_argument An argument or a value nested in it has the wrong JSON type, or a value its schema does not list
400 id is too large for a 32-bit integer
400 No model is loaded
400 The most recently used model is not a llama.cpp model
404 The model is unloaded while the request waits for it
500 The backend reports an error; the backend's own status replaces this one when it sends one
500 The request fails unexpectedly

POST /v1/tokenize

Tokenizes text without using the model's context window. After a request to a reranker, for example, the reranker's tokenizer answers.

Requires LEMONADE_API_KEY when it is set.

Parameters

Parameter Required Description Status
content Yes The text to tokenize.
add_special No Insert special tokens, such as BOS. Defaults to false.
parse_special No Tokenize special tokens; false treats them as plain text. Defaults to true.
with_pieces No Return each token's text piece with its ID. Defaults to false.

Example

Invoke-WebRequest `
  -Uri "http://localhost:13305/v1/tokenize" `
  -Method POST `
  -Headers @{ "Content-Type" = "application/json" } `
  -Body '{"content": "This is a string to tokenize"}'

curl http://localhost:13305/v1/tokenize \
  -H "Content-Type: application/json" \
  -d '{"content": "This is a string to tokenize"}'

Response: 200 OK

{"tokens": [1986, 374, 264, 914, 311, 77651]}

Response format

  • tokens - Token IDs, or {"id", "piece"} objects when with_pieces is true.

Errors

Status Code When
400 invalid_json The body is not a JSON object
400 missing_argument A required argument is missing
400 invalid_argument An argument or a value nested in it has the wrong JSON type, or a value its schema does not list
400 No model is loaded
400 The most recently used model is not a llama.cpp model
404 The model is unloaded while the request waits for it
500 The backend reports an error; the backend's own status replaces this one when it sends one
500 The request fails unexpectedly
